# 每日日记定时任务配置

这套模板用于把每日日记流程交给具有调度与 Agent 执行能力的平台。仓库没有内置调度器；下载、初始化或运行导航脚本不会创建任务。

## 包含什么

| 文件 | 用途 |
|---|---|
| [单次执行提示词](../templates/automations/daily-diary.prompt.md) | 每次运行的完整工作范围、取证、回写与通知规则 |
| [调度参数示例](../templates/automations/daily-diary.schedule.example.json) | 平台无关的配置清单；不是任何产品可直接导入的 API/配置文件 |
| [创建请求模板](../templates/automations/daily-diary.create-task.md) | 填好后交给支持定时任务的助手或平台 |

JSON 中 `enabled: false` 表示示例尚未启用，不会改变平台任务状态。它不包含任务 ID、账号、真实记忆、主机路径或固定模型名称。所有 `<...>` 占位符都必须由部署者在私人环境中替换，宿主不会因读到此文件自动展开它们。

## 配置步骤

1. 按 README 初始化独立私人知识库，先运行 `tools/validate.py` 与 `tools/refresh.py`。
2. 选择真正能访问私人知识库的执行环境，填写绝对根目录、IANA 时区和授权材料范围。新增连接来源需单独配置账号权限，模板不提供凭据。
3. 复制参数示例到自己的私人配置位置，修改 `timezone` 与 `schedule.local_time`。示例为 `Asia/Shanghai` 每天 `23:30`，只是示例，不代表作者当前任务。源目录和连接来源默认空列表，需按实际授权填写。
4. 将单次提示词占位符替换，检查授权范围后保存完整正文到调度平台。若采用文件引用，先核验每次运行都能读取该文件；后续文件更新不会自动改变平台已保存的提示词副本。
5. 配置为**独立任务，每次新聊天**。选择模型与推理策略，设置单写者和仅必要时通知；检查是否已有同目标任务，避免重复。
6. 先手工执行一次，回读当日日记、来源缺口、导航和审计。确认后在平台启用，再检查真实定时触发及通知。

私人绝对路径、本机调度 ID、账号、连接标识、运行历史、水位与日志只保存在私人工作区，不提交公共模板。定时任务日期按时区计算，不能依赖机器默认时区。23:30 的运行只能覆盖截至该时刻的证据，不能声称完整覆盖尚未发生的全天；后续活动需人工决定是否另行补录，模板不自动回放历史。

## 按次选择模型

复杂度可参考材料量、来源数量、证据冲突和写入目标数量；重要性可参考决策影响与误记成本。常规少量材料选择足够完成取证和回读的模型；跨来源冲突或重要结论提高核验能力与推理强度。选择须在执行聊天启动前完成，记录当次配置和理由，避免固定某个会退役或不可用的模型名。

这是一项调度策略，不是提示词能自行实现的功能。平台若只支持每个任务保存一个模型/推理设置，则不等于支持每次动态选择；需要具有真实派发能力的适配器，或者由使用者明确接受固定配置这一偏差。未完成适配前不要宣称已满足按次选择，也不要把写在 JSON 中的策略当作已部署能力。本仓库不实现模型派发器。

## Codex / ChatGPT 桌面端示例

在支持该功能的桌面版本中，使用 Scheduled 创建独立定时任务，选择能访问私人知识库的本地环境，并保存替换后的任务提示词。需要本机文件的任务运行时，机器和应用需保持运行；网页端任务不能直接读取本机文件夹。独立任务每次启动新聊天。以上行为依据 [OpenAI 官方定时任务文档](https://learn.chatgpt.com/docs/automations)，核对日期为 2026-10-27；界面和可用性以实际账号为准。

官方文档支持默认或显式选择模型与推理设置，但不据此推断平台支持按次动态选型。具体选型策略与可用能力按上一节核验。通知规则属于执行意图；还须检查宿主通知设置是否真正支持静默。

不要把这个 JSON 直接写入产品内部配置目录，也不需要启用 API、另购服务或提供 API key 来阅读本模板。CLI、系统 cron 或其他调度器的使用者可以据此实现适配，但仅触发命令不等于已具备 Agent 执行、来源访问和按次选型能力。

## 可选：云端发起、本机执行

当授权来源分布在云端和本地时，可由具备派发能力的云端任务读取它获准访问的来源，形成含引用、时间与缺口的摘要，再派发**一个新的本机执行聊天**核验本地产物并回写。聊天摘要不能替代重要完成结论的权威证据。由上级统一通知一次，本机端只回传结果。

这是可选架构说明，不是已实现的连接器：须另行验证云端到本机的派发能力、机器在线状态、数据传输授权及费用。没有这些能力时采用可访问资料的本地执行方案，不能假设云端自动看见本机磁盘。

## 验收与故障处理

| 层次 | 需要的实际证据 |
|---|---|
| 配置保存 | 平台任务存在，时区、时间、环境、提示词和启用状态可回读 |
| 定时触发 | 计划时间产生新运行，且按要求是新聊天；核对实际时间和时区 |
| 业务完成 | 日记及相关文件已回读，来源和阶段有依据，必要审计与导航一致 |
| 通知送达 | 需通知时既定渠道实际收到一次；静默场景未发主动通知 |

手工试运行不证明定时触发；平台创建成功不证明执行或通知成功。来源失败不推进成功水位，保留未查/空结果/不可读等不同缺口。部分完成分别报告，不标记全链路成功。发现并发写入时保留待合并补丁；先解决冲突再继续。

本次仓库验证仅检查模板结构、占位符、链接和初始化复制，不创建真实任务、不读私人来源，也不承诺实际触发或通知已验收。
