# 项目路由与任务知识回写

## 背景检索

先判断回答是否依赖已有事实，再判断项目归属。涉及既有经历、项目成果、既有方案、复盘与延续工作时，先实际读取匹配资料，再提出个性化结论或索取可能已经存在的材料。用户指定只用给定材料时遵从其边界。

按入口和索引 → 当前记忆页 → 已映射目录的相关材料 → 必要关联来源的顺序有限检索。跨项目任务分别取证；找不到唯一回写目标不阻塞读取。不全盘扫描个人文件。

记录来源时间与核验时间；区分未查、未找到、不可读和已读取。目录名、修改时间和历史摘要是线索，不足以证明当前状态。

## 项目路由

优先采用用户指定的目标和已核验上下文。存在冲突时查 `index/projects.json` 的 ID、名称和别名，以及私人 `index/local-paths.json` 的机器目录映射。

项目身份、工作目录、当前知识目标分别核对。目录缺失只阻塞依赖该目录的操作；不得猜测替代目录。权威目标尚未核验时可读现有材料，但不能把候选地址当作已授权写入地址。

每个项目保留一个当前权威知识目标；其他页面放链接。历史来源保留日期，不整批复制成当前结论。

## 回写与授权

只有使用者已经授权的本地维护范围内，才回写证据支持的新决策、规则、已验证里程碑、可复用办法和重要产物位置。普通问答、未采纳方案、重复内容和无新事实不强写。个人画像、外部系统和云端发布不由本地维护授权覆盖。

先重读目标，保留已有有效内容，精确合并变更。事实写项目页，稳定经验写 `memory/决策与经验/`，日记写 `memory/日记/YYYY/MM/YYYY-MM-DD.md`。索引只保存路由信息，不重复整段状态。

每条新知识保留来源、来源日期、核验日期和状态。待验证项不晋升为已完成。发生并发变更时重新合并；已知同一目标被多会话写入时采用单一写者，不能协调则留下待提交补丁。

## 验证与留痕

写后回读受影响章节；索引变化运行 `python3 tools/validate.py`，导航变化运行 `python3 tools/refresh.py` 并回读。脚本成功不等于事实核验通过。

一次逻辑变化记录一条审计，包含时间、目标、依据、变化和验证结果；不复制完整正文、账户数据或密钥。可复用项目现有 Git 记录，否则使用 `audit/knowledge-updates.jsonl`。仅在目标、必要索引和审计全部成功后报告同步完成。失败保留补丁及缺口，业务交付与同步分别说明。
